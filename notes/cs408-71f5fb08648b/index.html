65. 2026-10-22 跨篇概念一致性续审

本轮不重复 P098～P115 的全页复核，而是交叉检查了 TCP 序号、IPv4 分片与 ICMP、HTTP 请求依赖、操作系统进程/线程共享状态，并抽查数据结构 Dijkstra 与网络 OSPF、操作系统/组成原理的 TLB 与缺页有效访问时间，以及两科中断/异常的口径。后面三组本轮未确认新增冲突；前面四组发现了需要统一的边界：

  • P111 原 PDF 第 2 页把 TCP seq 概括为数据首字节序号。依据 RFC 9293 补全例外：若 SYN 与数据同段，seq 是 SYN 的序号，数据从 seq+1 起；FIN 在数据后占 1 个序号。运输层知识图改写笔记中的字段表、计算关系与复盘也同步统一，不能只在题型篇修正一处。
  • 网络层总纲原先把 DF=1 且 MTU 不足时“丢弃并返回 ICMP”写成必然。现区分丢弃与回报：普通允许回报的单播报文应返回类型 3/代码 4；广播/多播、非首片、ICMP 差错本身等禁止回报，依据 RFC 1812。这与 P111 已写明的 TTL/ICMP 禁发边界保持一致。
  • P113 原 PDF 第 3 页把“主 HTML 完整到达后才能请求引用对象”用作离散 RTT 题的时序前提。现明确 6/4/16/3 RTT 等旧例仍按原题模型计算，但不能把它升级为真实浏览器的必然规则：浏览器可流式解析、预扫描 HTML，发现 URL 后即可能开始请求。应用层知识总纲的网页对象与 RTT 表也同步限定模型；补注依据 HTML Standard。
  • 操作系统 P045《进程与线程》把共享内存一概写作必须互斥、把线程一概写作内核 CPU 调度单位。现限定为并发修改共享可变状态且存在写入时须安排同步；纯并发读取不因共享而需要互斥。纯用户级线程由用户态库调度，内核调度其承载实体；同进程线程各有栈，但栈仍在共享地址空间，不等于彼此内存隔离。
